One task. Cooperating agents.

Target architecture

Different perspectives, brought together.

The goal is to share suitable work across agents and bring their results back into one coding workflow. Core owns placement and resources; OpenCode provides the tool and session workflow.

{{cooperation_picture}}

Explore

Find relevant code, context and possible approaches.

Develop

Propose changes and carry out authorized work.

Review

Examine proposals, test results and remaining uncertainty.

Bring the results together.

These roles explain the intended cooperation; they are not three verified remote services available today.

Protected cooperation for private projects is part of the goal. Confidential execution on other participants’ devices is not implemented yet.

Your project. Explicit boundaries.

You control what is shared, what can be done and what stays private.

{{lock_icon}}

Scoped access

Work is limited to the selected project and its authorized tools.

{{approval_icon}}

Approved actions

Edits and commands follow explicit permissions. New authority is needed when an action falls outside the agreed scope.

{{shield_icon}}

Deliberate sharing

Public work uses explicitly reviewed inputs. Private files and history are not silently added.

Your source, prompts, tool results and history do not automatically become public cache or training data.

The current coding conversation executor runs locally. A separate public-work route uses an explicitly enrolled snapshot; it does not provide confidential remote execution of private code.

What does public work mean?

Only the exact inputs reviewed for public sharing are enrolled. The agent cannot silently add private files or conversation history to that snapshot. Public task sharing and protected private execution are different capabilities.

A bounded local coding task

A real local model has completed a read, edit and test task through OpenCode on a public test project. The original tests stayed unchanged, an independent check passed, and the recorded lifecycle checks completed.

The recorded CPU trial took about 37 minutes. It demonstrates this bounded task, not general coding quality or competitive speed.
